# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Todo PWA: several todo lists per person, offline-first (localStorage when signed out), Google sign-in **or** username + password accounts (no email, no personal info) with cloud sync to Postgres, lists shareable with view/edit roles by invitation. Gradle (Groovy DSL) multi-project: `backend` (Spring Boot 4, Java 25, **JDBC only, no JPA**, Postgres, Flyway) and `frontend` (React + plain JavaScript/JSX + Material UI, built with Vite). Java package: `ca.antany.app.todo`. Sibling project `/home/antany/expense-tracker` uses the same plumbing (auth, PWA, podman, test base); copy patterns from it, do not depend on it. Usage and deployment notes for people: `docs/usage-and-deployment.html`.

## Commands

Node is **never run on the host**: every npm command runs in a `node:22` podman container via Gradle `Exec` tasks (`frontend/build.gradle`). Don't run `npm` directly; use Gradle.

```bash
podman kube play podman/postgres.yaml     # local Postgres (todo/todo/todo) on host port 5433
./gradlew :backend:bootRun                # builds the frontend first, serves app + SPA on :8080 under /todo
./gradlew :frontend:dev                   # Vite dev server on :5173, proxies /todo/api, /todo/oauth2 to :8080
./gradlew :backend:bootJar                # backend/build/libs/backend-0.1.0.jar with the React bundle under static/
./gradlew :backend:processResources       # fastest way to rebuild only the frontend bundle (vite build)
./gradlew :backend:test                   # all backend tests
./gradlew :backend:test --tests ca.antany.app.todo.SyncTest
```

App URL: `http://localhost:8080/todo/` (context path `/todo`, must match `base` in `frontend/vite.config.js`). Restart the app after backend changes; frontend-only changes are picked up by re-running `:backend:processResources` (Spring serves the classpath dir). There is no lint or type-check task: the frontend is plain JS, so mistakes only show up at runtime. Exercise UI changes in a real browser rather than trusting a green build.

Tests use Testcontainers Postgres through **rootless podman**; start the socket first: `systemctl --user start podman.socket` (`backend/build.gradle` sets `DOCKER_HOST` and disables Ryuk). The app and the test JVM force UTC (`TimeZone.setDefault`, `-Duser.timezone=UTC`) because Postgres rejects legacy zone ids like `Canada/Eastern`.

Browser testing used host `chromium --headless=new --remote-debugging-port=9222` plus `puppeteer-core` run **inside a node podman container** with `--network=host` (connect with `browserURL`). Scratch scripts live in the session scratchpad, not in the repo.

## Architecture

**Build coupling:** `backend:processResources` depends on `:frontend:npmBuild` and copies `frontend/dist` into the jar's `static/`. The SPA is served same-origin by Spring, so auth is a plain session cookie + CSRF token (no CORS, no JWT).

**Auth (`auth/`, `user/`):** Google sign-in only (Spring Security `oauth2Login`, OIDC); no passwords. The SPA's `/login` page links to `/oauth2/authorization/google`; Google returns to `/login/oauth2/code/google`; success redirects to `/all`. `SecurityConfig` wires a custom `OidcUserService` calling `UserProvisioning.provision(...)` on each sign-in: requires `email_verified`, links by Google `sub`, claims a **placeholder** `app_user` (same email, null `google_sub`, created when someone is invited before ever signing in), and enforces `app.allowed-emails` (`APP_ALLOWED_EMAILS`, empty = open) for brand-new people (invited people always pass). Failures redirect to `/login?error=<code>` (`not_allowed`, `email_not_verified`, `account_conflict`). `CurrentUser.get(principal)` resolves the user by principal name = Google `sub`; unknown user = 401. API answers 401 (no redirects); logout is `POST /api/auth/logout`; CSRF uses `CookieCsrfTokenRepository` + `CsrfCookieFilter`, and `frontend/src/api.js` echoes the `XSRF-TOKEN` cookie as `X-XSRF-TOKEN`. Credentials: `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`. Behind a proxy set `SERVER_FORWARD_HEADERS_STRATEGY=framework` so the redirect URI uses https. **The real Google round trip has never been run** (no OAuth client yet); the password flow is browser-tested.

**Password accounts (`auth/PasswordAccounts`, `AuthController`, `LoginThrottle`):** alternative to Google, stored as `app_user.username` (lowercase, `[a-z0-9][a-z0-9._-]{2,29}`, unique case-insensitively) + `password_hash` (bcrypt via `PasswordEncoderFactories.createDelegatingPasswordEncoder()`, stored as `{bcrypt}...`); `email` and `google_sub` stay null. Endpoints (all JSON; CSRF still required): `POST /api/auth/register` (201, signs in), `POST /api/auth/login`, `POST /api/auth/password` (change; needs current password), public `GET /api/auth/options` -> `{google, passwordSignup}` (the login page hides the Google button when no client id is configured). Password rules: 8+ chars, at most 72 UTF-8 bytes (bcrypt limit), not equal to the username. Login failures all return `401 "Wrong username or password"` and a dummy hash is checked for unknown users so timing does not reveal them. `LoginThrottle` (in memory, resets on restart): 5 failures per username and 30 per IP per 15 min, 10 registrations per IP per 15 min, then 429 (the IP is `getRemoteAddr()`, so behind a proxy `SERVER_FORWARD_HEADERS_STRATEGY=framework` must be set or everyone shares one IP). `APP_PASSWORD_SIGNUP=false` (`app.password-signup`) turns registration off. **There is no password reset (no email); an operator can only set a new `{bcrypt}` hash in the DB.** Google and password accounts are separate people; there is no linking. A password session's principal name is `u:<user id>` (`CurrentUser.PASSWORD_PREFIX`), a Google one's is the Google `sub`; always resolve people through `CurrentUser.get(principal)`. `AppUser(id, googleSub, email, username, displayName)`: null `googleSub` no longer means "placeholder" on its own; a placeholder has an email and no username/hash.

**Persistence is JDBC only:** repositories are plain classes using `JdbcClient` with SQL text blocks and `RowMapper`s (`user/UserRepository`, `sync/SyncRepository`). Schema is Flyway (`db/migration/V1__init.sql`); never edit an applied migration, add a new `V<n>`. All client-creatable rows use **client-generated UUID primary keys**. Timestamps bind as `OffsetDateTime` (pgjdbc does not take `Instant`) and are read back with `getObject(col, OffsetDateTime.class)`. Jackson here is **Jackson 3** (`tools.jackson.databind.json.JsonMapper`). Tags/activity detail go through `cast(:x as jsonb)`.

**Sync (`sync/`)** is the heart of the app. `POST /api/sync` body `{cursor, changes:{lists,tasks,subtasks,activity}}` -> `{cursor, changes, rejected[]}`, one transaction:
- Writes are **last-write-wins per row** by client `updatedAt` (clamped to now + 5 min, truncated to ms); upserts are `insert ... on conflict (id) do update ... where table.updated_at < excluded.updated_at`; a tie keeps the server row. Deletes are tombstones (`deleted = true`), so an older edit cannot resurrect a deleted row. Merge is per row, not per field.
- Every write takes a new value from the global `change_seq` sequence (`seq` column). The pull cursor is the sequence's current value. `SyncRepository.lock()` takes a **transaction advisory lock** so seq order equals commit order; without it a slow transaction could commit a lower seq after a client already moved its cursor past it. **Anything else that changes synced rows must take the same lock and take a fresh `seq`.**
- Pull returns rows with `seq > cursor` that the user can see (own lists + lists where they are an ACCEPTED member), plus the server's current copy of any pushed row that lost or was rejected (so the client converges).
- Access gate `list/ListAccess.roleOf(user, list)` (OWNER / EDITOR / VIEWER / NONE; empty = list missing). Only ACCEPTED members count; a pending invitation grants nothing. Only the OWNER may change list properties; EDITOR may change tasks/subtasks/activity; VIEWER nothing. Bad rows come back in `rejected` (`forbidden`, `invalid`, `missing_parent`) instead of failing the request. Activity rows are append-only; the server stamps `actor_id` itself.
- **Sharing (`share/`):** `ShareService` + `ShareController`. `GET/POST /api/lists/{id}/members` (invite by email, or by username when there is no `@`; unknown email creates a placeholder user), `PATCH/DELETE /api/lists/{id}/members/{userId}` (owner changes role/removes anyone; a member may delete only themselves = leave), `GET /api/invitations`, `POST /api/invitations/{listId}/accept|decline`. Strangers get 404, non-owners 403. Mutations take the sync lock; **accept re-stamps `seq` on the list and all its tasks/subtasks/activity, a role change re-stamps the list row**, so devices with an old cursor re-pull them. Removal needs no stamp: every sync response carries `memberOf` (ids of lists shared with the user) and `store.applySync` drops local lists whose `role` is EDITOR/VIEWER but are not in it. Pulled list rows carry `role` (OWNER/EDITOR/VIEWER) and `ownerName`; local lists without a role count as owned. The client greys out edit controls for VIEWER (`canWrite`, `isOwner` in `db/store.js`; `TaskSheet` wraps fields in a disabled fieldset); the server enforces it anyway.

**Local-first client (`frontend/src/db`, `sync/`):**
- `db/store.js` is the single source of truth, persisted in `localStorage` key `todo.v1` (`{lists,tasks,subtasks,activity}`); `useStore()` returns the whole state, components derive with selectors (`liveLists`, `listTasks`, `subtasksOf`, `openTasks`, ...). Every mutation stamps `updatedAt` and sets `dirty: true`; deletes are tombstones; ordering uses fractional `position` (a drag only rewrites the moved row, renumbering when neighbours are < 1e-6 apart). The app works the same signed out and signed in.
- Completing a repeating task (`repeatRule` != NONE and `dueAt` set) spawns the next occurrence; `undoComplete(id, spawnedId)` reverts both. Activity entries are logged by the store (`created`, `edited`, `status_changed`, `completed`, `reopened`, `follow_up_set`, `followed_up`, `moved`).
- `sync/engine.js` runs only while signed in: pushes dirty rows and pulls on start, ~2 s after a local mutation (debounced), on `online`, on tab visible, and every 60 s. `store.applySync` acks pushed rows (only if not edited since), handles rejections (take server copy, or drop the row if the server won't show it; `invalid` just clears dirty; `missing_parent` stays dirty), and applies server rows unless the local row is dirty and newer. Server timestamps are normalised to JS ISO strings.
- Device/account guard: `localStorage` key `todo.sync` holds `{userId, cursor}`. First sign-in merges local data into the account. A different account on a used device pauses sync and shows `AccountSwitchDialog` (add the data to this account = `markAllDirty`, or start clean = `resetData`). First sync (cursor 0) pulls before pushing and drops the untouched starter list (`seed: true`) if the account already has lists, so new devices don't create duplicate "My tasks".
- Session (`session.jsx`): `/api/me` on load and when back online; the account is cached in `todo.me` so the app still looks signed in offline; only a real 401 signs out. The app never requires sign-in.

**Frontend (`frontend/src`):** plain JSX + MUI, custom indigo/cyan theme in `theme.js` (gradient app bar, glow background, glassy cards, floating bottom nav; all colours derive from `brand` + `buildTheme(mode)`). `themeMode.jsx` owns the System/Light/Dark preference (`localStorage` key `todo.theme`, toggle button in the app bar) and updates the `theme-color` meta tag. Landing page and first nav item is **All tasks** (`/all`, all lists grouped, list chips, search, show-completed). Other routes: `/lists`, `/lists/:id`, `/today`, `/upcoming`, `/follow-up`, `/settings`, `/login`. Bottom navigation on phones, permanent drawer from `md` up. Task details (due, follow-up, remind, repeat, tags, subtasks, activity) are in the bottom sheet `components/TaskSheet.jsx` opened by tapping a task title; native `<select>` and `datetime-local` inputs keep it mobile-friendly and easy to drive from tests, and inputs carry `name` attributes. Undo toasts come from `toast.jsx`.

**SPA routing:** `web/SpaController` forwards the client routes to `index.html`. **A new frontend route must also be added there** (and to `SpaForwardingTest`) or refresh/bookmarks 404. `web/ManifestController` serves `/manifest.webmanifest` as `application/manifest+json`.

**PWA:** `vite-plugin-pwa` precaches only the app shell. The service worker's `navigateFallbackDenylist` must keep `/todo/api/`, `/todo/oauth2/` and `/todo/login/oauth2/` so the Google redirects and API are never answered with `index.html`. Any new server-handled path (and any test-only path) needs the same treatment: a browser *navigation* to an undeclared server path is answered by the service worker with the SPA shell. Installing on a phone needs HTTPS or localhost.

## Testing conventions

Integration tests extend `IntegrationTestBase` (one shared Postgres container; `signUp(name)` provisions `<name>@test.local` like a Google sign-in and returns an OIDC-authenticated `MockHttpSession`; `signIn(email, sub, name)` for custom identities). Pass the session and `csrf()` explicitly on each MockMvc request. Use unique names per test (the database is shared across classes); `SyncTest` uses a random suffix. `SyncTest` inserts membership rows directly; `ShareTest` uses the real endpoints (invite then accept). `AllowListTest` and `SignupDisabledTest` use `@TestPropertySource`. MockMvc has no error dispatch, so assert error text with `status().reason(...)`, not a JSON `message`. `PasswordAuthTest` covers register/login/lockout/change/CSRF. `AuthIntegrationTest.csrfCookieIsHandedOutForTheSpaToEcho` has failed twice in ~10 full-suite runs and never in isolation (6/6 clean) or in 6 later full runs; cause not found. If it flakes again, investigate rather than retry.

## Things to know

- Browser tests of signed-in screens need a throwaway dev-login shim (a `@Profile("devshim")` controller that provisions a user and stores an OIDC `SecurityContext` in the session; call it with `fetch`, not navigation). **Never commit it**; delete it and restart without the profile afterwards.
- Reminders: `remindAt` is stored and synced but no notification fires yet. Web push in the background is out of scope.
- Postgres dev DB can be wiped with `drop schema public cascade; create schema public;` and a restart (Flyway rebuilds it).
- **Spring Boot 4 renamed the error-message property:** use `spring.web.error.include-message: always` (the old `server.error.include-message` is silently ignored, so API error messages like `"Wrong username or password"` never reach the browser). The sibling expense-tracker still uses the old key.
- When driving forms with puppeteer on a phone viewport, submit with Enter: the fixed bottom navigation can sit over a lower button and swallow the click.
- Don't `pkill -f <pattern>` from a tool shell if the pattern appears in the command line; it kills the shell. Use `pgrep -f '[T]odoApplication'` and `kill`.

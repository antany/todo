Build and deploy to a Raspberry Pi

One multi-arch image (x86-64 and ARM 64-bit) built with podman, run as a rootless pod on a Pi.

1. How it fits together

The app is a single Spring Boot jar that already contains the React bundle. A jar is the same bytes on every CPU, so you build it once; only the container base image (the JVM) differs per architecture. The image is published as a manifest list with two entries, linux/amd64 and linux/arm64, and each machine pulls the one that matches it.

PieceImageamd64arm64
Apptodo-app (built here, base eclipse-temurin:25-jre)yesyes
Databasepostgres:17yesyes
Tunnel (optional)cloudflare/cloudflaredyesyes
The Containerfile has no RUN steps on purpose, so building the arm64 variant on an x86 PC needs no QEMU emulation and takes seconds. It runs as unprivileged uid 10001.

Pod layout: app, postgres and tunnel share one network namespace and publish nothing on the host; the only way in is the Cloudflare Tunnel (see section 10 of the main guide for other reverse proxies).

2. Prepare the Raspberry Pi

Hardware and OS

  • Pi 3, 4, 5 or 400 (or Zero 2 W only for a quick trial: 512 MB is too little for JVM + Postgres). 2 GB RAM minimum, 4 GB comfortable.
  • 64-bit OS is required: Raspberry Pi OS (64-bit) / Debian 12+ / Ubuntu Server arm64. The 32-bit image cannot run the arm64 containers. Check with uname -m: it must print aarch64.
  • Put the database on an SSD or good USB drive if you can. Postgres on an SD card works but wears the card; at the very least use an A1/A2 rated card and keep nightly backups off the card.

Install podman and enable boot-time user services

sudo apt update
sudo apt install -y podman uidmap slirp4netns passt cron
podman --version                  # 4.4+ needed for Quadlet; Debian 12 has 4.3, see the note below

# let your user's containers start at boot and survive logout
sudo loginctl enable-linger $USER
Debian 12 (bookworm) ships podman 4.3, which predates Quadlet. Use Debian 13 / Raspberry Pi OS trixie / Ubuntu 24.04+ (podman 4.9 to 5.x), or skip section 8 and use podman generate systemd instead.

Give the JVM a memory cap

Containers inherit the Pi's RAM, and Java sizes its heap from it. On a 2 GB Pi, cap it so Postgres keeps room. In podman/todo-pod.yaml, add to the app container's env:

        - { name: JAVA_TOOL_OPTIONS, value: "-Xmx384m -XX:+UseSerialGC" }

Use -Xmx768m on 4 GB or more. Startup takes 20 to 40 s on a Pi 4; that is normal.

3. Prepare the build machine

Any x86-64 or arm64 Linux box with JDK 25 and podman works (Node is not needed; npm runs in a node:22 container through Gradle). The Pi itself can be the build machine, it is just slower (the frontend build takes a few minutes).

git clone <your-repo-url> todo-app && cd todo-app
java -version         # 25
podman --version
You only need QEMU (qemu-user-static + binfmt) if you later add a RUN step to the Containerfile. Without it, cross-arch builds work as is.

4. Build the multi-arch image

The script builds the jar and then both platforms into one manifest list:

scripts/build-multiarch.sh                       # local manifest: localhost/todo-app:latest
scripts/build-multiarch.sh ghcr.io/YOU/todo-app:1.0 --push     # build and push to a registry

What it does, if you prefer to run the steps by hand:

./gradlew :backend:bootJar          # builds the React bundle into backend/build/libs/backend-0.1.0.jar

podman manifest rm localhost/todo-app:latest 2>/dev/null || true
podman build --platform linux/amd64,linux/arm64 \
    -f podman/Containerfile --manifest localhost/todo-app:latest .

podman manifest inspect localhost/todo-app:latest | grep -E '"(architecture|os)"'
#   "architecture": "amd64", "os": "linux"
#   "architecture": "arm64", "os": "linux"
Both variants were built and the amd64 one was started as uid 10001 on Java 25 while writing this guide. The arm64 variant was built but not run (no Pi was available), so do the first-boot check in section 7 on the Pi.

Push to a registry (podman login ghcr.io first). --all is required, otherwise only the manifest list for your own architecture is uploaded:

podman manifest push --all ghcr.io/YOU/todo-app:1.0 docker://ghcr.io/YOU/todo-app:1.0

5. Get the image onto the Pi

Option A: through a registry (recommended)

A private GHCR/Docker Hub repo works, or run your own with podman run -d -p 5000:5000 docker.io/library/registry:2 (plain HTTP registries need insecure = true in /etc/containers/registries.conf.d/ on the Pi). On the Pi:

podman login ghcr.io
podman pull ghcr.io/YOU/todo-app:1.0
podman tag  ghcr.io/YOU/todo-app:1.0 localhost/todo-app:latest   # name used by podman/todo-pod.yaml

Podman picks the arm64 entry automatically. Check: podman image inspect localhost/todo-app:latest --format '{{.Architecture}}' prints arm64.

Option B: no registry, copy a tarball

Build just the Pi's variant, save it, and copy it over:

# on the build machine
./gradlew :backend:bootJar
podman build --platform linux/arm64 -f podman/Containerfile -t localhost/todo-app:latest .
podman save -o todo-app-arm64.tar localhost/todo-app:latest
scp todo-app-arm64.tar pi@raspberrypi.local:

# on the Pi
podman load -i todo-app-arm64.tar

Also copy the deploy files: scp -r podman scripts pi@raspberrypi.local:todo-app/ (or clone the repo on the Pi).

Option C: build on the Pi itself

git clone <your-repo-url> todo-app && cd todo-app
./gradlew :backend:bootJar
podman build -f podman/Containerfile -t localhost/todo-app:latest .

6. Secrets and configuration

cd ~/todo-app
cp podman/secrets.example.yaml podman/secrets.yaml
chmod 600 podman/secrets.yaml
nano podman/secrets.yaml
KeyMeaning
db-passwordRequired. Use a long random string: openssl rand -base64 24. It is read by both Postgres (on first start only) and the app.
tunnel-tokenCloudflare Zero Trust > Networks > Tunnels > your tunnel. Point its public hostname at http://localhost:8080. Remove the tunnel container from the pod if you use something else.
google-client-id, google-client-secret, allowed-emailsOptional. Leave out for username/password only. Redirect URI for Google: https://YOUR-HOST/todo/login/oauth2/code/google.
Changing db-password later does not change the password inside an existing Postgres data volume. Either change it in Postgres too (ALTER USER) or wipe the volume.

Other settings (APP_PASSWORD_SIGNUP, APP_ALLOWED_EMAILS, cookie flags) are in podman/todo-pod.yaml; the full list is in the main guide.

7. Run the pod

podman kube play podman/secrets.yaml podman/todo-pod.yaml

podman pod ps
podman ps --format '{{.Names}}  {{.Status}}'      # todo-app, todo-postgres, todo-tunnel
podman logs -f todo-app                          # wait for "Started TodoApplication"

First-boot check on the Pi (nothing is published on the host, so test from inside the pod):

podman exec todo-app sh -c 'uname -m; java -version 2>&1 | head -1'     # aarch64, openjdk 25
podman exec todo-postgres pg_isready -U todo
# then open https://YOUR-HOSTNAME/todo/ from a phone

Need to try it on the LAN before the tunnel is set up? Add ports: [{ containerPort: 8080, hostPort: 8080 }] to the app container, open http://raspberrypi.local:8080/todo/, and remove it again afterwards. Sign-in cookies are marked secure, so test sign-in over HTTPS or temporarily set SERVER_SERVLET_SESSION_COOKIE_SECURE to "false".

Stop and remove (the database volume is kept): podman kube down podman/todo-pod.yaml.

8. Start at boot (Quadlet)

With linger enabled (section 2), a Quadlet .kube file makes systemd start the pod on every boot and restart it if it dies. Use absolute paths:

mkdir -p ~/.config/containers/systemd
cat > ~/.config/containers/systemd/todo.kube <<'EOF'
[Unit]
Description=Todo app pod
After=network-online.target
Wants=network-online.target

[Kube]
Yaml=/home/pi/todo-app/podman/secrets.yaml
Yaml=/home/pi/todo-app/podman/todo-pod.yaml

[Service]
Restart=on-failure
TimeoutStartSec=300

[Install]
WantedBy=default.target
EOF

systemctl --user daemon-reload
systemctl --user start todo.service
systemctl --user status todo.service
journalctl --user -u todo.service -f
Replace /home/pi with your home directory. Quadlet units are generated, so there is no enable step: the [Install] section is enough. If your podman does not accept two Yaml= lines, run podman kube play podman/secrets.yaml once by hand (secrets persist in podman) and keep only the pod file in the unit.

Reboot once and confirm the app comes back by itself: sudo reboot, then podman ps.

9. Backups

chmod +x scripts/backup-db.sh
BACKUP_DIR=/mnt/usb/todo-backups scripts/backup-db.sh     # try it once
crontab -e
# 15 3 * * *  BACKUP_DIR=/mnt/usb/todo-backups /home/pi/todo-app/scripts/backup-db.sh

Keep the backup folder on a different device than the database (USB stick or network share), otherwise a dead SD card takes both. Restore: gunzip -c todo_<stamp>.sql.gz | podman exec -i todo-postgres psql -U todo todo.

10. Updating to a new version

  1. On the build machine: git pull, then scripts/build-multiarch.sh ghcr.io/YOU/todo-app:1.1 --push.
  2. On the Pi: scripts/backup-db.sh, then podman pull ghcr.io/YOU/todo-app:1.1 and podman tag ghcr.io/YOU/todo-app:1.1 localhost/todo-app:latest (or podman load a new tarball).
  3. Recreate the pod: systemctl --user restart todo.service, or by hand podman kube down podman/todo-pod.yaml && podman kube play podman/secrets.yaml podman/todo-pod.yaml.

Database migrations (Flyway) run automatically on start. Rollback: re-tag the previous image as latest and restart; if a release added a migration, restore the pre-update backup too, because Flyway migrations are not reversed.

11. Troubleshooting

SymptomCause and fix
exec format errorWrong-architecture image (for example an amd64 tarball loaded on the Pi). Rebuild with --platform linux/arm64, or use the manifest list. Also confirm uname -m is aarch64, not armv7l (32-bit OS).
Registry pull gets the wrong arch / "no image found for architecture"The push was missing --all, so the manifest list was not uploaded. Push again with podman manifest push --all.
App killed (exit 137) or Pi freezesOut of memory. Set JAVA_TOOL_OPTIONS (section 2), add swap, or use a Pi with more RAM.
App restarts with "password authentication failed"The Postgres volume was created with a different db-password. See the warning in section 6.
Everything works but sign-in loops or redirects to http://Keep SERVER_FORWARD_HEADERS_STRATEGY=framework and serve over HTTPS.
Pod does not start after rebootloginctl enable-linger $USER not set, or the unit cannot reach the network yet: journalctl --user -u todo.service.
Rootless build fails with "no subuid/subgid"Install uidmap and add ranges: sudo usermod --add-subuids 100000-165535 --add-subgids 100000-165535 $USER, then podman system migrate.
Part of the Todo app docs. See also usage and deployment.

2. Using the app

Getting around

On a phone, use the bottom bar; on a larger screen, the side menu. All tasks is the first item and the page the app opens on.

  • All tasks: every task from every list, grouped by list. Tap list chips to narrow to one or more lists, search across everything, and use the toggle to show completed tasks. The sort button orders by manual order, due date or priority.
  • Lists: your lists. Tap + to create one (name and colour); the pencil edits a list.
  • Today: open tasks due today, with overdue ones on top.
  • Upcoming: tasks due later, grouped by day.
  • Follow-up: tasks to chase. "Due for follow-up", "Scheduled", and "Waiting" tasks that have no date.
  • Settings: sync status, backup export/import, and clearing this device.

Adding and completing tasks

  • Open a list, type in Add a task and press Enter. The quick-add box takes only a title; set dates in the task details.
  • Tick the checkbox to complete a task. A bar at the bottom offers Undo for a few seconds.
  • Drag the handle on the right of a task to reorder (works when the sort is "Manual order" and no search or tag filter is on).

Task details: due date, follow-up and more

Tap a task's title (not the checkbox). A panel slides up with:

FieldWhat it does
NotesFree text.
ListMove the task to another list.
PriorityNone, Low, Medium, High. Shown as a coloured flag; can be used as the sort order.
StatusTo do, In progress, Waiting, Done. "Waiting" tasks appear in the Follow-up view.
DueDate and time. Overdue tasks are highlighted in red. Chips set Today, Tomorrow or Next week in one tap.
Follow upThe date you want to chase this task. Appears in the Follow-up view and as a highlighted chip when it is due.
Remind meA reminder time. Stored and synced; notifications are not wired up yet (see limitations).
RepeatDaily, weekly, monthly or yearly. Needs a due date. Completing the task creates the next one; Undo removes it again.
TagsType a tag and press Enter. Tags can be filtered on in a list and searched on All tasks.
SubtasksA small checklist; the task row shows progress such as 1/3.
Follow-up & activityWrite a note and press Log follow-up to record that you chased it. The history lists every change (created, edited, status changes, follow-ups). Logging keeps a future follow-up date and clears one that has already passed, so set the next date after logging.

Changes save immediately; close the panel with the ✕.

Creating an account and signing in

Signing in is optional. Use the Sign in button in the top bar:

  • Create account: choose a username (3 to 30 characters: letters, digits, dot, dash, underscore; not case-sensitive) and a password of at least 8 characters, and repeat it. Nothing else is asked or stored: no email, name or phone number.
  • Sign in: the same username and password on any device. Too many wrong attempts lock sign-in for that username for about 15 minutes.
  • Continue with Google: shown only when the site owner has set up Google sign-in. A Google account and a username account are separate accounts; they cannot be merged.
  • Change password: Settings → Change password (asks for the current one).
There is no password reset. Because no email is kept, a forgotten password cannot be recovered by the app. Use a password manager or write it down. (The server operator can set a new password hash directly in the database, see section 11.)

Install on your phone or computer

Open the site over HTTPS (or localhost) and choose Add to Home screen / Install app in the browser menu. The app then opens full-screen and works offline.

Sharing a list

Sign in, open a list and tap the person+ icon. Type a Google email or, for a username account, the username (usernames never contain an @), pick Can edit or Can view and tap Invite. Nothing is visible to the other person until they accept: they see an envelope icon with a count in the top bar, open it and choose Accept or Decline. Accepted lists appear in their Lists and All tasks pages marked as shared.

  • Can view: read everything, change nothing (the add box, checkboxes and task fields are disabled).
  • Can edit: add, edit, reorder, complete and delete tasks. Only the owner changes the list itself.
  • The owner can change a role or remove someone at any time; a member can choose Leave list.
  • Inviting an email that has never signed in leaves the invitation waiting for them; it appears after their first Google sign-in.

3. Offline, sync and accounts

  • Not signed in: everything is stored in this browser only. Nothing leaves the device. Clearing site data deletes it, so use Settings → Export JSON as a backup.
  • Signed in (username and password, or Google): your lists sync with your account about two seconds after a change, when the connection returns, when you come back to the tab, and every minute. The top bar chip shows Synced, Syncing, Offline or Problem; tap it to sync now.
  • Offline while signed in: keep working. Changes are saved on the device and uploaded when the connection returns.
  • Existing local lists when you sign in (either method) are kept and merged with your account, not discarded. A fresh device does not get a duplicate starter list.
  • Conflicts: if the same task is edited on two devices, the most recent edit wins for that whole task; deletions win over older edits. Edits to different tasks never conflict.
  • A different account on the same device: the app asks whether to add this device's lists to the new account or start clean. Starting clean only empties this device.
  • Signing out keeps the lists on the device.

4. Running it locally (development)

Requirements: Java 25, podman. Node is not needed on the host; npm runs in a container through Gradle.

# 1. database (Postgres on host port 5433, user/password/db all "todo")
podman kube play podman/postgres.yaml

# 2. build the React app, then start the server (serves everything)
./gradlew :backend:bootRun
#    open http://localhost:8080/todo/

# optional: hot-reloading UI on :5173 (proxies the API to :8080)
./gradlew :frontend:dev

# tests (need the rootless podman socket)
systemctl --user start podman.socket
./gradlew :backend:test

Without Google credentials the app is fully usable signed out; the "Continue with Google" button redirects to Google but cannot complete. To try real sign-in locally, create an OAuth client (section 6) with the redirect URI http://localhost:8080/todo/login/oauth2/code/google and start the app with GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET set.

5. Deployment: overview

The whole app is one executable jar: Spring Boot serves the API and the built React bundle from the same origin. It needs one Postgres database and an HTTPS front door.

phone / laptop  --HTTPS-->  reverse proxy or tunnel  -->  app (jar, :8080, path /todo)  -->  Postgres 17
                            (Caddy, nginx, Cloudflare Tunnel)

Recommended target, matching the existing expense tracker: one rootless podman pod on your own server holding three containers (app, Postgres, Cloudflare Tunnel), nothing published on the host except through the tunnel. A plain systemd service running the jar next to an existing Postgres works just as well.

Files for the container route (podman/Containerfile, podman/todo-pod.yaml, podman/secrets.example.yaml, scripts/backup-db.sh) are not in the repo yet; they are step 7 of the plan. The snippets below are the intended content, modelled on the expense tracker's.

Only one app instance is needed for personal or family use. Sync requests are serialised by a database lock, which also makes it safe if you ever run two instances against one database.

6. Google sign-in setup (optional)

Username and password accounts work with no setup at all. Google sign-in is an extra: until GOOGLE_CLIENT_ID is set, the login page simply hides the Google button. To enable it:

  1. In the Google Cloud console, create a project and configure the OAuth consent screen (External; add yourself and family as test users, or publish).
  2. Create credentials → OAuth client ID → type Web application.
  3. Authorised redirect URI: https://YOUR-HOST/todo/login/oauth2/code/google (exactly; add the http://localhost:8080/... one too for local testing).
  4. Copy the client ID and secret into the secrets file (below). Never commit them.
  5. Set APP_ALLOWED_EMAILS to a comma-separated list of the Google emails allowed to create an account. Leave it empty to allow anyone with a Google account. People you invite to a list will always be allowed in once sharing exists. (This list does not apply to username accounts; use APP_PASSWORD_SIGNUP for those.)
The real Google round trip has not been exercised yet. Test it first on localhost, then on the public URL, before inviting anyone.

7. Configuration reference

All settings are environment variables on the app container (Spring maps them onto application.yml).

VariableDefaultPurpose
DB_URLjdbc:postgresql://localhost:5433/todoJDBC URL. In the pod use jdbc:postgresql://localhost:5432/todo.
DB_USER / DB_PASSWORDtodo / todoDatabase login. Use a strong password in production.
GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRETnot-configuredOAuth client from section 6. Required for sign-in.
APP_ALLOWED_EMAILSempty (anyone)Who may create an account.
APP_PASSWORD_SIGNUPtrueWhether anyone can create a username + password account. Set false on a private instance after you and your family have registered (existing accounts keep working).
CONTEXT_PATH/todoURL prefix. Must match base in frontend/vite.config.js (rebuild the frontend if you change both).
SERVER_FORWARD_HEADERS_STRATEGYunsetSet to framework behind a proxy so redirect URIs use https and the login lockout sees each visitor's real IP instead of the proxy's.
SERVER_SERVLET_SESSION_COOKIE_SECUREunsetSet to true in production so the session cookie is HTTPS-only.
SERVER_PORT8080Listening port.

The database schema is created and upgraded automatically at start-up (Flyway). The Postgres user needs rights to create tables in its database.

8. Build and package

./gradlew :backend:bootJar
# -> backend/build/libs/backend-0.1.0.jar   (React bundle included, about 32 MB)

Runtime needs Java 25. To containerise (planned podman/Containerfile):

FROM docker.io/library/eclipse-temurin:25-jre
RUN useradd --system --uid 10001 app
COPY backend/build/libs/backend-0.1.0.jar /app/app.jar
USER app
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "/app/app.jar"]
podman build -f podman/Containerfile -t localhost/todo-app:latest .

9. Run in production

Option A: podman pod (recommended)

Planned podman/secrets.example.yaml (copy to the git-ignored podman/secrets.yaml and fill in):

apiVersion: v1
kind: Secret
metadata:
  name: todo-secrets
stringData:
  db-password: change-me
  google-client-id: 1234-abc.apps.googleusercontent.com
  google-client-secret: GOCSPX-change-me
  allowed-emails: you@gmail.com,family@gmail.com
  tunnel-token: eyJ-change-me          # only if you use a Cloudflare Tunnel

Planned podman/todo-pod.yaml:

apiVersion: v1
kind: Pod
metadata:
  name: todo
spec:
  containers:
    - name: app
      image: localhost/todo-app:latest
      env:
        - { name: DB_URL, value: "jdbc:postgresql://localhost:5432/todo" }
        - { name: DB_USER, value: todo }
        - { name: DB_PASSWORD, valueFrom: { secretKeyRef: { name: todo-secrets, key: db-password } } }
        - { name: GOOGLE_CLIENT_ID, valueFrom: { secretKeyRef: { name: todo-secrets, key: google-client-id } } }
        - { name: GOOGLE_CLIENT_SECRET, valueFrom: { secretKeyRef: { name: todo-secrets, key: google-client-secret } } }
        - { name: APP_ALLOWED_EMAILS, valueFrom: { secretKeyRef: { name: todo-secrets, key: allowed-emails } } }
        - { name: APP_PASSWORD_SIGNUP, value: "true" }     # set "false" to close registration
        - { name: SERVER_FORWARD_HEADERS_STRATEGY, value: framework }
        - { name: SERVER_SERVLET_SESSION_COOKIE_SECURE, value: "true" }
    - name: postgres
      image: docker.io/library/postgres:17
      env:
        - { name: POSTGRES_DB, value: todo }
        - { name: POSTGRES_USER, value: todo }
        - { name: POSTGRES_PASSWORD, valueFrom: { secretKeyRef: { name: todo-secrets, key: db-password } } }
      volumeMounts:
        - { name: data, mountPath: /var/lib/postgresql/data }
    - name: tunnel                       # remove if you use another proxy
      image: docker.io/cloudflare/cloudflared:latest
      args: ["tunnel", "--no-autoupdate", "run"]
      env:
        - { name: TUNNEL_TOKEN, valueFrom: { secretKeyRef: { name: todo-secrets, key: tunnel-token } } }
  volumes:
    - name: data
      persistentVolumeClaim:
        claimName: todo-db-data
podman kube play podman/secrets.yaml podman/todo-pod.yaml
podman logs todo-app          # look for "Started TodoApplication" and Flyway migrating
# stop / remove:  podman kube down podman/todo-pod.yaml

To start the pod at boot with rootless podman, generate a systemd unit (podman generate systemd or Quadlet) and run loginctl enable-linger $USER.

Option B: plain jar + systemd

[Service]
User=todo
Environment=DB_URL=jdbc:postgresql://localhost:5432/todo DB_USER=todo
EnvironmentFile=/etc/todo-app.env      # DB_PASSWORD, GOOGLE_*, APP_ALLOWED_EMAILS (chmod 600)
Environment=SERVER_FORWARD_HEADERS_STRATEGY=framework SERVER_SERVLET_SESSION_COOKIE_SECURE=true
ExecStart=/usr/bin/java -jar /opt/todo-app/app.jar
Restart=on-failure

10. HTTPS and reverse proxy

HTTPS is mandatory in practice: Google requires it for redirects, and phones only offer to install the PWA on HTTPS.

  • Cloudflare Tunnel: add a public hostname pointing at http://localhost:8080 (inside the pod). Requests for /todo/... pass through unchanged.
  • Caddy / nginx: proxy https://YOUR-HOST/todo/ to http://127.0.0.1:8080/todo/ and send X-Forwarded-Proto and X-Forwarded-Host. Caddy example: reverse_proxy /todo/* 127.0.0.1:8080.
  • Do not strip or rewrite the /todo prefix; the app expects it.

11. Backups, upgrades, rollback

Backups

Two layers: each person can export JSON from Settings, and you back up the database. A nightly dump from the running pod (planned scripts/backup-db.sh, same idea as the expense tracker's):

podman exec todo-postgres pg_dump -U todo todo | gzip > ~/backups/todo/todo_$(date +%F).sql.gz
# keep the newest ~14, run from cron or a systemd timer, and copy off the machine
# restore into an empty database:
gunzip -c todo_2026-11-01.sql.gz | podman exec -i todo-postgres psql -U todo todo

Upgrading

  1. Take a database backup.
  2. git pull, then ./gradlew :backend:bootJar and rebuild the image.
  3. Restart the pod/service. Flyway applies any new migrations automatically at start-up.
  4. Open the app, check the sync chip shows Synced. Installed PWAs pick up the new version on their next load.

Rollback

Flyway migrations here are forward-only. To roll back after a schema change, redeploy the previous image and restore the pre-upgrade backup. Never edit a migration that has already been applied; add a new one.

12. Security and privacy notes

  • Two kinds of account. Username accounts store only the username and a bcrypt hash of the password (never the password itself); no email or personal data. Google accounts store the Google email, display name and Google account id, never a password.
  • Password guessing is slowed down: 5 wrong attempts per username and 30 per IP address lock sign-in for about 15 minutes, and registrations are limited per IP. The counters live in memory and reset when the server restarts. Error messages do not reveal whether a username exists.
  • There is deliberately no password reset (no email on file). If someone forgets their password, the operator can store a new bcrypt hash for that username in the app_user table (prefixed {bcrypt}), and should tell the person to change it in Settings straight away. Prefer testing this on a throwaway account first.
  • Close open registration with APP_PASSWORD_SIGNUP=false once your people have accounts.
  • The session cookie is HttpOnly and, with the setting above, HTTPS-only. State-changing requests require a CSRF token (handled by the app).
  • Every server request to read or write a list passes a single permission check: only the owner and accepted members can see it; a pending invitation grants nothing; viewers cannot write.
  • Use APP_ALLOWED_EMAILS to keep a private instance private.
  • Keep podman/secrets.yaml and any env file out of git (already in .gitignore) and readable only by the service user.
  • Browser-stored data (signed out, or cached while signed in) is plain text in localStorage: anyone using the same browser profile can read it.
  • Never ship a development login shortcut; the project's browser tests use a temporary one that must not be committed.

13. Go-live checklist

  1. Domain and HTTPS in place; https://YOUR-HOST/todo/ loads the app.
  2. Google OAuth client created with the exact redirect URI; consent screen configured.
  3. Secrets filled in; strong DB password; APP_ALLOWED_EMAILS set.
  4. Pod/service started; logs show Flyway migrating and "Started TodoApplication".
  5. Sign in with your Google account; chip shows Synced.
  6. Create a task on one device, see it on another; go offline, edit, reconnect, confirm it syncs.
  7. Install the PWA on a phone.
  8. Backup job scheduled and a restore tested once.
  9. Auto-start at boot verified (reboot test).

14. Known limitations and roadmap

  • Sharing: only the owner can rename, recolour or delete a shared list and manage its members. A list holds at most 50 members. If someone is removed, the list vanishes from their devices on their next sync, including any edits they had not synced yet.
  • Reminders need the app open. Due reminders and follow-ups show in a “Due now” card on All tasks (snooze or dismiss), and, if you switch on Show notifications in Settings, as system notifications while the app is open in the background. A fully closed app cannot notify you: that needs a push server, which this project does not have.
  • Merge is per task, not per field: two devices editing different fields of the same task while offline will keep only the later edit.
  • Google sign-in untested end to end until an OAuth client exists. Username sign-in is tested end to end.
  • No password reset or account recovery for username accounts, by design. Google and username accounts cannot be linked.
  • PWA icons are placeholders copied from another project; replace before sharing widely.
  • The unit of "task group" is a list; there are no nested lists or folders.

15. Troubleshooting

SymptomLikely cause and fix
Google says redirect_uri_mismatchThe URI in the Google console must equal https://HOST/todo/login/oauth2/code/google. Behind a proxy, set SERVER_FORWARD_HEADERS_STRATEGY=framework so the app builds an https URI.
"Too many attempts" when signing inThe username or IP hit the failure limit. Wait about 15 minutes, or restart the server to clear the in-memory counters. Behind a proxy, make sure SERVER_FORWARD_HEADERS_STRATEGY=framework is set, otherwise all visitors look like one IP.
"Creating accounts is turned off"APP_PASSWORD_SIGNUP is false.
Forgot the password of a username accountIt cannot be reset by the app. See section 12 for the operator procedure, or create a new account.
Login page shows "not allowed to sign up"The email is not in APP_ALLOWED_EMAILS. Add it or leave the variable empty.
Refreshing a page gives 404A new frontend route was added without adding it to web/SpaController.

Chip shows ProblemTap it to retry; check the app logs. A 401 means the session ended and you will be asked to sign in again; your local data is kept.
